このコンテキストリポジトリの git 操作を、**非エンジニアでも安全に**一気通貫で行うスキルです。「保存したい」「最新にしたい」「push が失敗した」のいずれにも対応します。専門用語をそのまま報告に使わず、平易な言葉で結果を伝えます。

> 前提: このリポジトリは複数人が同時に更新し、Backlog/GitHub/Figma 等の**同期ミラーが自動で書き込む**ため、履歴が枝分かれ（分岐）しやすい。分岐は下の事故防止規約に従って機械的に解決する。手順そのものは素の git で足りるので、ここでは**規約と判断基準だけ**を定める。

## 何をするか（意図を汲んで実行する）

- **保存したい** → 変更を確認 → `git add -A` → 変更内容にふさわしい**日本語1行**のコミットメッセージを自分で考えて commit → push。push が分岐で失敗したら下の規約で rebase してから push し直す
- **最新にしたい** → リモートの最新を取り込む（`git pull --rebase`。マージコミットを増やさない）
- **push が失敗した（non-fast-forward）** → リモートを取り込んでから push し直す（下の規約）

未コミットの変更があるのに最新化したい等、操作が競合する場合は、勝手にコミット・破棄せず状況を伝えて確認する。

## 同期ミラーの衝突解決規約（事故防止・変えないこと）

分岐は必ず **`rebase`**（マージコミットを作らない）で解決し、履歴を一直線に保つ。同期ミラーの自動生成ファイルは頻繁に衝突するので、内容を理解して**機械的に**解決する。

- **同期ミラー（`課題管理/`・`開発/`・`デザイン/inventory/` 等）の衝突は、原則リモート（最新側）を採用する**。これらは正本ツール（Backlog・GitHub・Figma）から再生成されるミラーで、手元の版に固執する意味がないため
- **追記専用のログ（`*.log` 等）は両方の行をすべて残す（union）**。一方を捨てるとログが消失する
- **タイムスタンプ（`lastUpdated` 等）は新しい方を採用**、ローカル絶対パス（`outputDir` 等）は churn を減らすためリモート側を残す
- 競合マーカー（`<<<<<<<` `>>>>>>>` `=======`）の消し残しが無いことを確認してから続行・push する

## 重要な制約

- **`--force` / `--force-with-lease` での強制 push は行わない**（他人・同期ミラーのコミットを消す恐れがあるため）
- 手元の未保存の変更を、ユーザーの確認なしに破棄しない
- **自動生成でないファイル**（手書きのドキュメント・課題本文・Gold層レコード等）の衝突は、上の機械的規約の対象外。勝手に判断せず、内容を提示してユーザーに確認する
- 機密情報を含むファイル（`.env` 等）が変更に含まれていたら、コミット前に必ず確認する
- やり直したいときは `git rebase --abort` で元に戻せる
