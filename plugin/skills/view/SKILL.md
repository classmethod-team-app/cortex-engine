# View

Claude Code の回答は、長くなるほどチャットの中では読みにくく、**そのままでは他人に渡せません**。`view` は、その内容を**共有できる成果物**（単一のHTMLファイル）に変換します。ブラウザで開いてそのまま見せられますし、印刷ダイアログからPDFにもできます。

## 設計の核: HTMLはAIが書かない

このスキルの実体は、同梱の変換スクリプト `scripts/render.mjs`（Markdown文字列 → スタイル適用済みの自己完結HTML）です。**AIがHTMLを書き起こすことはしません**。毎回HTMLを生成させると、遅く・不安定で・高コストになるためです。

AIの役割は次の2つだけです。

1. 変換したいMarkdownを用意する（既に回答済みならその本文をそのまま使う）
2. タイトルとテーマ（レイアウト種別）を決める

## いつ使うか

**毎回は使いません。** 短い応答・一問一答・作業の途中経過は、そのままチャットで返してください。

使うのは、次のように「人に見せたい・残したい」ときだけです。

- 大きめの調査結果・比較検討（選択肢の比較表・トレードオフ整理）
- 設計方針・実装方針のまとめ、レビュー結果の一覧
- 会議や関係者に共有したい報告・レポート
- ユーザーから「HTMLにして」「共有できる形にして」「ブラウザで見たい」と頼まれたとき

### 呼ばれていないときの振る舞い: 実行せず、1行で申し出る

ユーザーがこのスキルの存在を覚えていなくても使えるように、**次の回答を返したあとは、共有用HTMLにできることを1行だけ添えます**。

- 表を2つ以上含む回答
- 比較検討・調査結果・方針のまとめ

```
この内容は共有用のHTMLにできます（/view）。出しますか？
```

**勝手に生成しないこと。** 判断はユーザーに委ね、求められたときだけ実行します。申し出は1行に留め、同じ会話で断られたら以降は申し出ません（しつこくしない）。

> 文字数の多さだけを理由に申し出ないでください。長い技術的な説明はチャットで読む方が速いことも多く、HTMLが効くのは**構造がある**（表・比較・段階の整理）ときです。

## 実行手順

### 1. 出力する内容をMarkdownで用意する

**すでに回答した内容をHTML化する場合は、その本文をそのまま使います。書き直さない・要約し直さないでください**（読み手が見るのは同じ内容であるべきで、変換のたびに文面が変わると信頼できません）。

Write ツールで一時ファイルに書き出します（例: `tmp/view-input.md`）。まだ書いていない内容なら、ここで普通にMarkdownとして書きます。

### 2. スクリプトに渡す

Skill 起動時に提示される **「Base directory for this skill」** の絶対パスを `<SKILL_DIR>` として、**リポジトリルートで**実行します。

```bash
node "<SKILL_DIR>/scripts/render.mjs" tmp/view-input.md --title "認証方式の比較検討"
```

主なオプション:

| オプション | 既定 | 内容 |
| --- | --- | --- |
| `--title "..."` | 入力の先頭見出し → ファイル名 | ページタイトル |
| `--theme report\|compare` | `report` | `report`＝1カラムの読み物 / `compare`＝`##` 見出しごとにカード化して2カラム比較 |
| `--root DIR` | `.` | 案件リポジトリのルート（デザイントークンと出力先の基準） |
| `--project NAME` | DESIGN.md の `name` → ルート名 | ヘッダーに出すプロジェクト名 |
| `--out PATH` | `tmp/view/{日時}-{slug}.html` | 出力先を明示指定する |

標準入力からも渡せます。

```bash
cat tmp/view-input.md | node "<SKILL_DIR>/scripts/render.mjs" --title "調査結果"
```

出力先は `tmp/view/{YYYYMMDD-HHmmss}-{slug}.html` です。**`tmp/` に置くのは、案件リポジトリの管理対象（コミット対象）を増やさないためです**（`tmp/` はgit管理外の作業領域）。

### 3. パスを報告し、ブラウザで開く

スクリプトは生成したファイルの絶対パスを標準出力に返します。そのパスをユーザーに報告し、ブラウザで開きます。

```bash
open "tmp/view/20260726-101530-認証方式の比較検討.html"
```

共有するときは、このHTMLファイル1つを渡せば完結します（外部のCSS・JavaScriptを一切参照しません）。印刷用のスタイルも入っているので、ブラウザの印刷ダイアログからPDF化できます。

## 生成物の見た目

案件リポジトリに `デザイン/DESIGN.md` があれば、そのフロントマター（`sync-designs` が生成するデザイントークン: `colors` / `typography` / `rounded`）を読み取り、CSS変数に流し込みます。案件のブランドカラー・フォントで出力されるということです。DESIGN.md が無い場合・値が読み取れない場合は、中立のデフォルトテーマにフォールバックします。

生成物の先頭には「いつ・どのプロジェクトで生成したか」が小さく表示されます。

## 対応するMarkdown記法

見出し（h1〜h4）・段落・箇条書き / 番号付きリスト（ネスト・チェックリスト可）・**強調** / `インラインコード`・コードブロック・表・引用・水平線・リンク。

**これら以外の記法は変換されず、エスケープされた素のテキストとして表示されます**（壊れることはありません）。本文に `<script>` などのHTMLが含まれていても、必ずエスケープされて「文字として」表示されます（実行されません）。凝った表現が必要なときも、スクリプトの範囲で表現できるMarkdownに寄せてください。**AIがHTMLを直接書いて渡すことはしないでください**（このスキルの前提が崩れます）。

## 注意

- 生成物は `tmp/` 配下のため**コミットされません**。恒久的に残したい内容は、Markdownとして適切な場所（`Cortex/` 配下等）に記録してください。HTMLは共有用の派生物です
- 内部限定情報（公開範囲ルール参照）を含む内容をHTML化して外部に渡さないでください。**渡しやすい形にするほど、渡す相手を間違えたときの影響が大きくなります**
