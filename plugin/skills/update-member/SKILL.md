プロジェクト関係者を `Cortex/Members/records/` 配下に **1人1ファイル** で登録・更新します。スキーマ・運用ルールは `Cortex/Members/README.md` を参照。

## 目的

文字起こしや議事録では、同じ人物が複数の表記（誤変換・下の名前・愛称）で現れる。名簿は**氏名の正式表記と表記揺れを1件にまとめる**ことで、AIが担当を取り違えるのを防ぎ、**人名正規化の唯一の根拠**になる（用語集が用語の揺れを束ねるのと同じ役割）。

> 夜間の `update-gold`（メンバーフェーズ）が、議事録・課題・外部ソースに現れた名簿未登録の人物を **`status: draft`** で自動起票する。本スキルは**人間の手動登録・更新の口**であり、draft の確認・`active` 昇格や、既存レコードの訂正（氏名・所属・役割・表記揺れの追記）を扱う。

## 実行手順

### 1. 既存の名簿を読み込む

`Cortex/Members/records/*.md` の frontmatter を読み、既存の `title` / `aliases` / `side` の集合を把握する（重複登録・表記揺れの照合に使う。件数が増えても frontmatter の grep で足りる）：

```bash
grep -hE '^(title|aliases|side):' Cortex/Members/records/*.md 2>/dev/null || true
```

### 2. 対象人物の情報を集める

`$ARGUMENTS` で人物（氏名・課題キー・議事録パス等）が指定された場合はそれを優先する。指定がない場合は、登録・更新したい人物について次を確認する：

- **氏名の正式表記**（`title`。スペースを含んでよい）と読み仮名（`yomi`。同姓の区別・音声認識の突合に使う）
- **所属**（`org`）と **side**（`cm`＝開発側 / `client`＝顧客 / `vendor`＝ベンダー）・**役割**（`role`）
- **表記揺れ**（`aliases`。文字起こしの誤変換・呼称）。議事録・文字起こしから拾えるものを集める
- 情報源が議事録・課題なら、その参加者欄・発言から分かる範囲で埋める。**確証が持てない項目は推測で埋めず空にする**

### 3. 既存レコードとの照合

集めた候補をステップ1の集合と照合する：

- **既存メンバーの新しい表記揺れ** → 新規ファイルを作らず、既存ファイルの `aliases` への追記を提案する
- **既存メンバーの定義変更**（所属・役割の変更、draft → active の昇格） → 既存ファイルの frontmatter・本文の更新を提案する（変更履歴は git が持つ）
- **新規メンバー** → `Cortex/Members/template.md` ベースの新規ファイルを提案する

### 4. プレビューと承認（必須）

登録・更新する内容（新規／aliases 追記／定義更新の別、ファイル名、`title`/`yomi`/`org`/`side`/`role`/`status`、本文）を提示し、ユーザーの承認を得てから書き込む。**承認なしに書き込まない。**

- AI が氏名・所属・side を確証を持って確認できない場合は、`status: draft` のまま残し、人間の確認を促す
- 本人・PM 等との対話で氏名・所属・side が確認できた場合に `status: active` にする（draft からの昇格はこのレビュー作業にあたる）

### 5. ファイルの作成・更新

- ファイル名: `records/{氏名（スペース無し）}.md`、ID: `member:{氏名（スペース無し）}`（例: `member:山田太郎`）
- `description` に「何者か」の1文（例: 「株式会社〇〇所属。PM。」）を必ず記入し、本文も空にしない（Viewer の個別ページに表示されるため）
- 離任しても削除せず `status: inactive` にする（過去の議事録・Decision の正規化根拠として残す）
- **コミット前に `node "<SKILL_DIR>/../../scripts/validate-cortex.mjs"`（プラグイン同梱リンター）を実行し、規約違反があれば修正してからコミットする**

## 注意事項

- **同一人物に複数ファイルを作らない**（表記揺れは `aliases` に集約する）
- **内部情報は書かない（顧客開放の境界）**: 名簿には氏名・所属・役割・表記揺れだけを書く。**人の評価・人事・単価・工数等の内部情報は絶対に書かない**（判断に迷う情報はそもそも置かない）
- 氏名・所属・side を推測で確定させない。確証が弱い項目は空にするか `status: draft` のまま残す
- frontmatter のフィールドは `Cortex/Members/README.md` で定義されたもの以外を追加しない
