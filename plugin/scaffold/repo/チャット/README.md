# チャット

Slack 等のチャットは**このリポジトリにミラーしません**。正本は常に Slack 側です（古いコピーを作らない／内部限定情報を顧客開放リポに持ち込まないため）。`開発/issues/` と同じ「道しるべ」方式です。

## 参照方法

対象チャンネルは `channels.json` に `{ "name": "...", "url": "..." }` の形で列挙し（`name` はどのチャンネルか分かるラベル）、Claude Code 等から **Slack MCP** でライブ取得します（Slack MCP の接続設定は cortex プラグインの `.mcp.json` 側）。

## 権限境界（公開範囲）

Slack MCP に接続できるのは**社内メンバーのみ**です。顧客はコネクタの権限を持たないため、ここからチャット内容を読むことはできません。**これが公開範囲の境界**になります。

> Slack を丸ごと貯めると内部限定の雑談・評価が漏れる。だから中身は置かず、読める人だけが MCP 経由でライブ参照する。

## セットアップ

対象 Slack チャンネルを `channels.json` に **`{ "name": "チャンネル名", "url": "リンク", "gold": true|false }` の形で**列挙します（複数可。`name` で「どのチャンネルか」が分かるようにする）。`/setup-project` のステップ9でも案内されます。

### `gold`（顧客が見る Gold 層へ蒸留してよいか）

**チャンネルごとに必ず判断して明示します。** 判断の質問はひとつだけ:

> **このチャンネルに顧客はいますか？**

- **顧客がいる（社外）** → `"gold": true`。顧客は既にその場の会話を見ているので、Gold に上げても新しく見えるものは無い
- **社内だけ** → `"gold": false`。社内限定の議論・見積・工数・評価が顧客の目に触れてしまう
- **迷ったら書かない**（宣言が無ければ対象外＝安全側。後から `true` にできるが、逆は履歴に残るため戻せない）

`gold` は上の MCP でのライブ参照や `notify`（自動通知）とは**独立**です。**読むことと、顧客に見せることは別の判断**として扱います。
